# 待办与已记录的问题（bookcard-share）

按 2026-11-07 的决定：**先把静态页做好**，下面这些先记着，不在这一轮动。

## 1. 文本场景的内容进不了 App（已记录，本轮不做）

**现象**：静态页里能看到文本场景的原文块 + 高亮（`source.context`），但导入
Flashcard App 之后这部分没了。

**根因**：App 的导入模型没有 scene/context 字段。
`00_flashcard/server-python/app/routes/imports.py:174-186` 的 `_CardIn` 只有
front / back / phonetic / pos / tags / difficulty / images / sort_order；
`_bulk_import_core` 也不写 `local_flashcards.scene_kind` / `scene_json`
（App 表里有这两列，`db.py:1198-1203`，但导入路径不碰）。
App 把 `local_flashcards.source` 硬编码成 `'import'`（`imports.py:863`）。

**影响面**：当前书库里 45 本书里**只有 1 本是 image 场景**（物理八年级），
其余全是 text 场景 ⇒ "预览即导入后所见" 对绝大部分书目前不成立。

**图片场景没这问题**：走 `images[].occurrences` + `width/height`，App 自己画
高亮框，这条链路实测是通的。

**将来要做的（三个选项，未拍板）**：
- a. 在 App 的导入路径补 scene 字段（改 `_CardIn` + 写 `scene_kind/scene_json`）
- b. 引擎侧把文本场景降级成 image 场景（拍板 #18 本来就说默认 image）
- c. 接受差异，静态页里标注"这段 App 里不显示"

**在 App 侧动手之前必须先解决的**：改 App 的导入路径 = 动 00_flashcard 的现有代码，
需要先拿到授权（当前子项目的硬约束是不动两个仓的现有代码）。

## 2. Pillow 依赖（已解决，不影响页面）

**当时问的是什么**：引擎原来用 PyMuPDF 出 jpg，但 PyMuPDF **编不了 webp**
（实测 `Pixmap.tobytes` 只支持 `png/pnm/pgm/ppm/pbm/pam/tga/tpic/psd/ps/jpg/jpeg`）。
所以要出 webp 就得引入 Pillow。

**结论**：**不影响静态页，也不影响引擎**。
- 静态页：纯 HTML/CSS/JS，跟 Pillow 一点关系没有。
- 引擎：没动它的依赖声明，也没动它的出图代码。
- 只有这个子项目的**构建步骤**（把包里的 jpg 转成 webp）要 Pillow，所以只写在
  `bookcard-share/requirements.txt` 里。

**如果将来要让引擎自己出 webp**，才需要决定 Pillow 是进正式依赖还是挂可选组
（`bookcard[images]`）——那是引擎的事，跟本子项目无关。

## 3. 公开包要不要带全书页图（未拍板）

契约规定 public 包禁书页图。若公开分享包也按"全书 webp"的口径，就跟契约冲突。
现在本子项目照契约走：public 包不产图片目录，HTML 里只有卡和文本块。

## 5. 全量抽词 + 全书审卡（2026-11-07，物理八年级）

在**目录看图 v1**（`train/data/tocv-quiz-v1/94a9b8d6b27d`，56 条 vision 目录）之上，
把 46_BookCard 的抽卡流程整条走了一遍，两道闸门都真拍板了：

| 步骤 | 结果 |
|---|---|
| 换入 vision 目录 → `toc_gate` | 批准；引擎四条判据全过（43 个 section 连续覆盖 9–231 页）|
| `sections_build` | 43 个 section（旧规则目录是 68 个脏名）|
| 试抽 9 段 → 审 35 张 → `trial_gate` | 合格率 97.1%、fatal 0，批准 |
| 全量抽词 207 段 | 641 个词，引擎丢弃 0（surface / evidence 全部逐字命中）|
| 全书审卡 | 517 张**逐张**判定（引擎的 `judge_next` 只发试抽那批，这里是自己出题）|
| 回修 | 删 38 个 reject/fatal 词，改 2 个 boundary，补 13 个漏标词 |
| 最终 | **482 张卡**，43 个词库，pass_rate 99.2%、fatal 0、定位率 98.6% |

### 这一轮用到的脚本（都在 `tools/`）

| 脚本 | 干什么 |
|---|---|
| `submit_trial.py` | 试抽交卷（带逐字校验：surface / evidence 必须在原文里）|
| `submit_trial_judge.py` | 试抽审卡交卷 |
| `submit_full.py` | 全量交卷：校验 → 提交 → 清章首页 |
| `make_judge_batches.py` | 把全书最终卡渲染成审卡批次（引擎只发试抽那批）|
| `merge_judge.py` | 合并全书判定 → `review/full-agent.jsonl` |
| `apply_review.py` | 按审卡结果回修答案并重交（删 / 改 / 补）|

### 踩到的坑

1. **Unicode 空格**：扫描件里有 U+2005 / U+2006，肉眼是普通空格但手打的
   evidence 对不上。**evidence 必须从原文精确截取**，不能手打。
2. **删掉的词会自己回来**：回修是从原始答案重算的，「按当前卡集反推要删什么」
   下轮就忘了删——必须按 `card_id`（`<fp12>:<sid>:<sha1(front)[:8]>`）哈希匹配，
   才跟卡集解耦。
3. **章首页要单独清**：只有「章名 + 小节名 + 页码」的页按版式处理，各块口径不一致，
   统一在 `submit_full.py` / `apply_review.py` 里清。
4. **引擎的 manifest 不带 toc**：分享包的目录是从工作目录的 `toc.json` 读的，
   所以 `printed_page` / `offset` 得由 `sharepack/toc.py` 自己认出来。

## 6. 确认页的设计（2026-11-07，《智能体设计模式》模拟时定的）

**确认页和最终页是同一个容器**：左栏照常在，只是还没有卡。
左栏在「没有卡」时列的是**目录的叶子**，标成**全路径**：

```
简介 | 前言
简介 | 什么是智能体系统？
智能体的特征 | Level 0：核心推理引擎
第 1 章：提示链（Prompt Chaining） | 提示链模式概述
```

- 右栏（目录）仍是多级树，**页号只给最下一级**（父级那行只表示分组）。
- 右栏改一条标题/页码/层级，**左栏立刻跟着变**（`tocChanged` → `renderPanel`）。
- `kind`（front / body / appendix）用来把前置页和附录挡在左栏之外
  （目录页自己、前言、译者序、参考文献都不算正文）。

**要改的地方（引擎侧）**：现在 `sections_build` 的 section 名字是条目自己的标题，
短节合并时用「 / 」拼（这就是上一版物理书那些「52 83 100 / 124 141 168」脏名的来处）。
按新设计，section 名字要是**目录路径**，分隔符用「 | 」，粒度取叶子级。

**又踩了一次 localStorage**：旧目录存在 `bookcard-share:<book_id>`，换包/改包后
旧目录会盖住新目录（这次是改了一版 HTML，旧目录没有 `kind` 字段，左栏多出「目录」一行）。
→ 存储 key 必须带**包指纹**，否则每次重新生成页面都可能踩。

**左栏没有「返回上一级」**：一本书一个 index 页，没有「Books 列表」那一级。
只有一本书时，左栏直接落在那本书的内容级（不用先点一下书名），顶部的
「‹ 书名」条不出现（多本书时才保留返回）。

## 7. 左栏 = 目录树（2026-11-07 定稿）

**左栏永远是目录树**，不是词库列表 —— 确认页和最终页长得一样：

```
目录修订页
欢迎进入物理世界
第一章 打开物理世界的大门 | 第一节 走进神奇   3
第一章 打开物理世界的大门 | 第二节 探索之路   24
第二章 运动的世界 | 第一节 动与静            17
```

- 目录叶子**按标题配对到词库**：配到的叶子右边显示卡数，点进去是那几张卡；
  没配到的（还没抽卡，或者引擎合并出来的）点一下跳到那一页看原文。
- **左栏层级不跟 scope 跳**：默认停在目录树那一级；只有用户自己点了某个词库
  才进卡片那一级。（以前 scope 一变就跳到 words —— 打开最终包只剩三张卡，看不见目录。）
- 引擎那套「3–25 页自动挑层 + 短节合并」保持不动；只改**命名**：
  section 名字取目录路径（` | ` 连接），和左栏对得上。

## 8. 目录层级选择（2026-11-07 定稿）

右栏目录头里一个「层级」下拉：

- **默认 = 本书实际用到的最大层级**（不是死板的 3）：
  物理那本目录只有两级 → 默认 2 级；《智能体设计模式》有四级 → 默认 4 级。
- 下拉给的是 `1 .. max(3, 本书最大层级)`，外加一项「＋ 增加一级」。
- **下拉选的是「显示到第几级」**（不是「只看这一级」）：
  选 2 级 = 显示 1、2 两级；选 3 级 = 显示 1、2、3 三级。
  - 右栏：1..L 级的条目都列出来，**页号只给最下一级**（L 级那批），
    更深的子条目不显示（它们的页号也就看不到）。
  - 左栏：同一批**叶子**（带页号的那批），仍是「父 | 子」全路径。
  - 左栏里配不上的词库（引擎合并出来的）只在默认层级追加，选别的层级时不追加。
- **「＋ 增加一级」** → 层级上限 +1，下拉多一项；之后循环点数字徽章就能调到新的一级。
- 徽章改层级时**视图跟着条目走**（切到新层级）并给一条提示 ——
  不然条目在按层级过滤的视图里「消失」，用户看着像没反应。

## 9. offset 的口径（2026-11-07 统一）

**offset = 前置页数（正数）**：**PDF 页 = 印刷页 + offset**，即 印刷页 = PDF 页 − offset。

- 页面上只显示正数（物理那本 7、《智能体设计模式》13）。
- 引擎里两套旧约定只差符号：页眉页脚探测是「印刷 − PDF」（负），
  看图锚点是「PDF − 印刷」（正）。**取绝对值两边都对**，所以读取时统一取绝对值。
- **印刷页号只有一个来源说了算：offset**。条目自带的 printed_page 只在
  offset 还没探到时顶一下 —— 否则用户改了 offset、那一栏的数字却不动。
- 顺手修好一个真 bug：物理包当前页的印刷页号一直是错的
  （PDF p.10 显示「印刷 17」，因为按「印刷 = PDF + offset」算；应为 3）。

## 10. 导出（edits.json）必须带全（2026-11-07 修）

原来 `payload.toc` 只在 `STORE.toc` 存在时才带 —— 而 `STORE.toc` 是**改过目录**才写的。
结果：**用户一条没改就导出，文件里没有目录**，agent 拿不到确认过的那份目录。

现在：
- **目录永远带**（没改过就带包里那一份），带 `offset` 和 `source`；
- **书的元数据也永远带全**（书名 / 领域 / 水平 / 标签 / 副标题），不只是改过的那几个。

「用户确认过」本身就是要交出去的东西 —— 改没改都要带走。

## 11. 标签编辑（领域 / 水平）2026-11-07 修

- **水平** = 下拉选（未标 / 小学 / 初中 / 高中 / 本科 / 硕博），不打字。
- **领域** = 自由文本，就地输入。
- 两个都直接指认自己那个 chip（不再「猜是哪个」——
  领域为空时猜会错位到水平上，把水平的下拉换成了输入框）。

## 12. 左栏第一行：「目录」（2026-11-07）

- 名字从「目录修订页」改成**「目录」**。
- 这一行**显示目录所在的页码**（p.2–13 这种区间，来自 agent 提取目录时记下的那几页），
  **点它跳到目录的第一页** —— 用户要拿书上的印刷目录跟右边这份逐条对。
  页码从哪来：`toc.json` 的 `pages` 字段，没有就去看工作目录的 `tocv.json`
  （看图 v1 的 `locate` 记下的 `toc_pages`）。
- 跳页要等 scope 切完再做 —— 切 scope 本身会把页码重置回 1。

**第三步（抽关键词）里，目录那几页不参与提取**：
目录页本身不是内容，抽出来的多半是章节标题和页码。引擎那边靠
「正文起止页」天然排掉（sections 只切正文），但流程里要写明这条，
别让抽词的范围越过目录页。

**水平的下拉只能开一次**：下拉出现在 chip 里，鼠标抬起时点击事件会冒泡回 chip，
再跑一遍 handler 就把下拉重建又拆掉（表现为「闪一下就没了」）。
chip 的 onclick 开一次就置空，并给下拉加 stopPropagation。
