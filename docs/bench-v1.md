# benchmark v1：选页规则与评分规则

维护者定，2026-11-06，细化 `docs/contract-v1.md` §8。本文件、`bench/v1/pages.json`、`prompts/bench_judge_v1.md` 三样合起来叫 **bench-v1**。三样里任何一样改了，或者 `src/bookcard/prompts/extract_v1.md` 升了版本，都要升成 bench-v2，新旧分数不放在一起比。

## 0. 冻结的东西

| 项 | 值 |
|---|---|
| 题目页清单 | `bench/v1/pages.json`（`bench/v1/select_pages.py` 生成，已入库，不再重跑） |
| 被测提示词 | `src/bookcard/prompts/extract_v1.md`（ex-v1） |
| 评审模型 | `MiniMax-M3`，`temperature=0`，`effort=max`（最高思考强度，接口已实测接受），`max_tokens=32768`，`KW_LLM_TIMEOUT=600`，每次评 1 页里最多 8 条；回包没有文本按“回包坏了”处理 |
| 评审提示词 | `prompts/bench_judge_v1.md`（bj-v1） |
| 金标准用的提示词 | 审核：`bookcard.judge.SYSTEM`（契约 §6）；补漏：`prompts/bench_missed_v1.md`（bm-v1）；参考解释重写：`prompts/bench_rewrite_v1.md`（br-v1）。三者都用评审模型同样的设置 |

评审模型不用被测里最常用的 `MiniMax-M3.1-Flash`（它就是我们现在的抽取器，也是金标准候选的来源），换成同一家的大模型 `MiniMax-M3`。`MiniMax-M3.1` 这个名字接口不认（已实测）。同一家的模型偏好问题还在，靠 §4 的人工复核兜底。

## 1. 选页（已执行，结果在 `bench/v1/pages.json`）

三本书各 30 页，共 90 页（英语有 11 页超过 1500 字被切块，共 101 个 seg）：

| 书 | fp12 | 目录 | 练习 | 注释多 | 正文 |
|---|---|---|---|---|---|
| 中外历史纲要（上） | 4ecda441f6d4 | 4 | 26 31 38 125 | 59 63 143 | 22 页 |
| 物理 九年级全册 | 2f3e20c2e34d | 4 | 13 86 102 149 | 30 45 63 | 22 页 |
| 英语（实为九年级全册） | dc221b94f843 | 10 | 22 54 102 110 | 137 139 141 | 22 页 |

规则（全部确定性，不用随机数）：

- **排序键** `h = sha1("bench-v1:<fp12>:<page>")`，"按 h 取"就是按这个十六进制串从小到大取。
- **能进池子的页**：`pages.jsonl` 里 `kind` 是 `body / exercise / appendix`，`candidates.jsonl` 里有这页（抽取失败、被内容过滤挡掉的页不进），文字 ≥ 150 字，乱码率 ≤ 5%（乱码 = 控制字符、私用区、未分配字符，以及 U+0400–U+1CFF 这些教材里不该出现的文字）。
- **目录 1 页**：`kind == toc`、文字 ≥ 150 字的页里按 h 取 1 页。
- **练习 4 页**：池子里 `kind == exercise`，或者某一行（去空白后）正好是这本书的练习栏目标题：历史「探究与拓展 / 问题探究 / 学习拓展」，物理「动手动脑学物理」（取字是乱码，脚本里按乱码原样认），英语「Self Check」。按 h 取 4 页。
- **注释多 3 页**：剩下的池子页打注释分，分 ≥ 1 的按分从高到低取 3 页，同分按 h。注释分：历史 = 「历史纵横 / 史料阅读 / 学思之窗」标题行数 + 行首圈码脚注数；物理 = 「小资料 / 科学世界 / 想想做做 / 想想议议 / 科学·技术·社会」标题行数 + 行首圈码脚注数；英语 = 首行是「Notes on the Text」的附录页里编号条目数。
- **正文 22 页**：剩下的 `kind == body`、不在练习池里、文字 ≥ 300 字的页按页码排好，等分成 22 段，每段按 h 取 1 页。这样全书前后都有。
- `pages.json` 每页记 `text_sha1`。评分时书页重新取字，`text_sha1` 对不上的 seg 不评分、报错，说明取字结果变了，要么修回去，要么升版本。

**训练隔离**：这 90 页的 seg 一律不进抽关键词模型的训练集和验证集。kwtrain 读数据时按 `pages.json` 剔除，并把剔除数写进 `metrics.json`。

## 2. 金标准 `bench/v1/gold.jsonl`

一行一个 seg：

```json
{"seg_id": "book:4ecda441f6d4:p0059", "fp12": "4ecda441f6d4", "page": 59, "chunk": 0, "stratum": "notes",
 "text_sha1": "…",
 "spans": [{"start": 41, "end": 45, "surface": "良渚文化", "type": "name",
            "ref_explanation": "…", "source": "candidate|missed|human"}]}
```

不存书页全文，只存偏移和 surface。每个词只存**首次出现**那一处。

做法（执行单另开）：

1. 候选：现成的 `candidates.jsonl`（ex-v1，MiniMax-M3.1-Flash）。
2. agent 审：按契约 §6 逐条判 `kw / expl`；`kw == accept` 进金标准。`boundary` 的由审的人改成正确边界后进金标准（`source: "human"` 或 `"missed"`），改不出来就不进。
3. 补漏：用评审模型 `MiniMax-M3` 对每页单独跑一遍"这页还有哪些值得学的词没列出来"，结果同样按 §6 审，通过的进金标准（`source: "missed"`）。这一步是为了压住金标准偏向 Flash 的问题。
4. 参考解释：每个金标准词带一条被判 `expl == 2` 的解释；候选里的解释不到 2 分的，由审的 agent 重写后再判。参考解释只供人工复核和日后对照，**不给评审模型看**，免得措辞像金标准的模型占便宜。
5. 人工抽检：the maintainer 每本书抽 6 页（共 18 页，占 20%）逐词看一遍，含漏标。人工判定覆盖 agent 判定。
6. 目录页的金标准固定为空，不审。

## 3. 抽词分

被测模型按 ex-v1 跑这 90 页的全部 seg，输出 candidates 格式（程序落偏移，同契约 §4）。

- 预测集合：每个 seg 里每个 surface 只取首次出现那一处（就是 `explanation` 不为 null 的那条）。
- 金标准集合：同上，`gold.jsonl` 的 spans。
- **只算非目录页**（87 页）。把每个非目录 seg 都放进 gold 字典，没有金标准词的放空列表，这样那页上的预测都算误报。被测模型某页失败（报错、回包不是 JSON），那页预测记空列表，召回照扣。
- 精确：`span_train.span_prf`，`(start, end)` 完全相同才算命中。
- 宽松：`span_train.overlap_prf`，有字符重叠就算命中。
- 主指标是**宽松 F1**（和抽词模型训练报告一致），精确 F1 并列报。
- 目录页单独报一个数：**目录页误标数**（3 页目录上的预测词总数），越少越好，不进 F1。
- 另按书、按层（正文 / 练习 / 注释）各报一份宽松 F1。

## 4. 依据分与解释分

**依据率**：分母 = 非目录页上全部预测词（首次出现那条）；分子 = 依据合格的。合格 = 两条都满足：

1. 程序能在 seg 原文里定位到依据句（`evidence` 偏移不为 null，定位规则同 `extract.locate_evidence`）；
2. 依据句和这个词"重叠或同句"：依据句的区间盖住了这个词的任意一处出现，或者和某一处出现落在同一句里。分句按 `。！？；!?;` 和"英文句点后跟空白"切，换行不算句末。

**解释分**：只评宽松命中的词。一个预测词和多个金标准词重叠时，取重叠字数最多的那个配对，每个金标准词只配一次。

1. 先程序判（结果覆盖模型）：
   - 没有解释 → 0；
   - 解释就是依据句，或互相包含（去空白后，同 `judge.Card.explanation_is_copy`）→ 0；
   - 字数（去空白）< 10 或 > 80 → 0；10–14 或 61–80 → 最高 1；
2. 剩下的交给评审模型按 bj-v1 打 0/1/2，取程序上限和模型分的较小值。评审模型回包坏了重试 2 次，还坏就记 0 并计入"评审失败数"。
3. 报两个数：**解释均分**（0–2）和 **0 分率**。

**评审一致率**：每次出报告，从被评分的解释里按 `sha1("bench-v1:judge:<model>:<seg_id>:<surface>")` 取最小的 10%（至少 30 条，最多 60 条），由 the maintainer 人工打 0/1/2（从审核 HTML 导出）。报**完全一致率**和**0 分判定一致率**（双方是否都判 0）。完全一致率低于 80% 时，这次报告的解释分标"评审不可信"，并改评审提示词升 bj-v2。

## 5. 成本与报告

- 被测跑分时用独立的空缓存（`KW_LLM_CACHE` 指向本次运行新建的文件），缓存命中不算 token、不算时间。
- 每次请求记 API 返回的输入 / 输出 token 和墙钟耗时；**失败率** = 最终失败的 seg 数 / 全部 seg 数（重试后仍失败才算）。
- 本地模型（例如抽关键词小模型）只出词、不出解释：依据率和解释分两栏填"—"。

报告 `bench/v1/reports/<日期>-<模型>.json` 加一张总表（`bench/v1/REPORT.md` 追加一行）：

| 模型 | 宽松 F1 | 精确 F1 | 目录页误标 | 依据率 | 解释均分 | 0 分率 | 每页输入 token | 每页输出 token | 每页秒数 | 失败率 | 评审一致率 |
|---|---|---|---|---|---|---|---|---|---|---|---|

"每页"都按 90 页平均。
